# 《字小乐》需求沉淀与决策记忆 Skill (LetterLearn Requirement Memory)

用于把已经讨论成熟的语文教学规范、产品交互与儿童心理设计决策沉淀在项目仓库内，使后续实现、回顾和跨对话可以先读取历史，而不是反复重新讨论。

---

## 🎯 适用场景

以下任一情况出现时激活本 Skill：
- 用户明确提出“记录下来 / 沉淀规则 / 方便后续使用”；
- 一个教学或交互主题已经过深入讨论，核心流程与边界基本敲定；
- 用户开始说“按这个做 / 可以开发了 / 规则就这么定”；
- 准备实现此前讨论过的功能（如自定义听写停顿节奏、错字消灭复习周期），需先确认既有决策；
- 新的教学需求推翻或调整了旧的规则。

---

## 📂 项目内沉淀文件路径

仅在项目仓库内读写规范文档：
- `docs/product/DECISION_INDEX.md`：全局产品与教学决策索引
- `docs/product/decisions/YYYY-MM-DD-topic.md`：具体主题决策文档

---

## 🚦 何时达到沉淀门槛

满足以下要点即可归档沉淀：
1. **解决的目标明确**（如：保护儿童视力、防止倒插笔、降低家长报听写负担）；
2. **核心业务流确定**（如：示范动画 $\rightarrow$ 描红纠偏 $\rightarrow$ 独立自测）；
3. **关键边界已界定**（如：笔画偏离容差半径、拼音声调不区分大小写但严格校验音标位置）；
4. **符合五位一体准则**（不幼儿化、不惩罚羞辱、大触控热区、60fps 性能）。

---

## 📝 沉淀内容标准结构

每份新决策文档（`docs/product/decisions/YYYY-MM-DD-<topic>.md`）包含：
- **背景与痛点**：为什么做？解决孩子/家长/老师的什么问题？
- **教学与课标要求**：对应部编版大纲要求、国标笔顺要求。
- **已敲定方案**：
  - 用户操作主流程
  - 核心界面与状态流转
  - 算法与参数界定（如时间、容差、倍速）
- **儿童心理安全边界**：错误如何温和提示？如何正向激励？
- **明确不做**：本期不做的边界。
- **验收标准**：如何验证落地效果。
