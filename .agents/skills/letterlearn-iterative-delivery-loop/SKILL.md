# 《字小乐》纵向迭代连续交付闭环 Skill (LetterLearn Iterative Delivery Loop)

把已经沟通成熟的一组需求持续执行到底，同时让每个迭代都有真实质量证据和可回滚 Git 提交。

核心不是“先把所有代码写完”，而是：

> **拆成少量纵向可运行迭代**  
> $\rightarrow$ 每轮开发 (Build)  
> $\rightarrow$ 测试构建 (Test)  
> $\rightarrow$ UI/儿童交互校准 (Calibrate)  
> $\rightarrow$ 五位一体教学与心理回顾 (Review)  
> $\rightarrow$ 工程反向自审找茬 (Inspect)  
> $\rightarrow$ 分类优化 (Improve)  
> $\rightarrow$ 回归验证 (Regress)  
> $\rightarrow$ 文档与上下文同步 (Sync)  
> $\rightarrow$ 独立原子提交 (Commit)  
> $\rightarrow$ **自动进入下一轮**  
> $\rightarrow$ 最后做跨迭代端到端总验收。

详细质量检查表和 execution record 模板见：
`references/quality-gates.md`

## 🎯 何时使用

优先用于：
- 已经形成可执行共识，用户说“按这个做 / 继续实现 / 直接落地 / 连做几版”；
- 一个复杂功能天然包含 2 个以上阶段（如听写系统升级、生字骨架算法优化、错题本与艾宾浩斯记忆强化）；
- 任务同时涉及业务状态、UI、语音/动画、测试或跨端适配；
- 用户希望一次沟通后连续完成，不想在半成品时每轮被追问“要不要继续”。

通常不用于：
- 单个小文案或微小样式修补；
- 还在发散讨论、核心方向未定的产品阶段；
- 明确缺少外部依赖且当前无法推进的任务。

---

## 🍰 必须是纵向切片 (Vertical Slices)

每轮迭代必须是**纵向端到端可运行的增量**，绝不能按横向技术层切片：

* ❌ **错误切片（横向分割）**：
  - I1 只写 TypeScript 接口；
  - I2 只写数据仓库；
  - I3 只写业务 Hook；
  - I4 才写 UI 组件；
  - I5 最后联调测试。
* ✅ **正确切片（纵向切片）**：
  - I1：实现最小可用字音拼音对齐展示 + 基础朗读 + 点击验证；
  - I2：接入田字格手写板 + 笔画实时同步 + 错笔温和提示；
  - I3：接入答对星级评分 + 墨滴增长 + 庆祝动效；
  - I4：接入错题本自动沉淀 + 艾宾浩斯强化练习入口；
  - I5：全链路真机与防误触校准 + 性能与安全区回归。

## 🔄 每轮固定执行状态机 (Fixed State Machine)

每轮必须严格执行以下步骤，不得跳步：

### A. Freeze — 冻结本轮目标
明确本轮要解决什么、用户可见变化是什么、验收标准是什么、本轮不做什么。

### B. Build — 实现纵向主路径
优先让完整主路径跑通，再补充边界条件。不制造冗余状态，不顺手大改无关代码。

### C. Test — 构建与模块测试
在《字小乐》中，必须运行：
```bash
pnpm run lint && pnpm run build
```
确保无 Lint 错误、TypeScript 类型无报错、构建打包成功。

### D. Calibrate — UI / 儿童交互校准
涉及 UI 时，调用 `letterlearn-child-ui-design` 检验：触控热区 $\ge 48\text{px}$、对比度达标、单屏单一任务、防误触。

### E. Review — 五位一体教学与心理回顾
对照语文名师标准与儿童心理学：
- 笔顺/拼音/注音是否严格符合部编课标？
- 是否具备示范-描红-自测脚手架？
- 有无可能打击孩子自信的负面反馈？

### F. Inspect — 工程反向自审（找茬）
主动找薄弱点，而非证明自己没错：
- 空数据、快速连续点击、网络离线、音频上下文未激活的处理；
- 状态是否由组件唯一持有，有无内存泄漏（如未清理的定时器或 HanziWriter 实例）。

### G. Improve — 分类优化
- **必须当前修**：影响主路径、导致崩溃、破坏儿童体验的问题，立即修好；
- **记录后续**：与本轮目标无关的巨型重构，记入待办，不拖慢本轮交付。

### H. Regress — 回归验证
修改优化后的代码，重新跑测试和构建验证，确保没有引入新 Bug。

### I. Sync — 同步长期上下文
按改动同步 `docs/engineering/IMPLEMENTATION_CONTEXT.md` 和执行记录。

### J. Commit — 独立原子提交
使用清晰的中文提交信息，确保工作区干净。

## ⏩ 连续自驱执行原则

用户授权整组需求后：
> **I1 提交后 $\rightarrow$ 自动推进 I2 $\rightarrow$ 自动推进 I3 $\rightarrow$ … $\rightarrow$ 最终验收。**

- **不中途无意义询问**：“已完成第 1 轮，请问要继续做第 2 轮吗？”（**必须自动继续推进！**）
- **只有遇到真实外部阻塞才能暂停**（如缺少必需的第三方凭据、需要用户做重大方向裁决、硬件环境不可用）。
- 遇到构建报错、测试失败或 UI 缺陷，均属于迭代中的正常修复动作，绝不是停下来的借口。
