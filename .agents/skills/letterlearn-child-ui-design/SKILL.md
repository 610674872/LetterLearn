# 《字小乐》儿童 UI 与交互设计守门 Skill (LetterLearn Child UI Design)

《字小乐》的项目级 UI / 交互质量守门 Skill。

> **核心哲学**：UI 不靠每次聊天临时修修补补。先执行儿童专属统一基线；一旦用户指出可复用问题，不仅修复当前界面，更排查全工程同类问题，并将经验蒸馏固化到项目设计规范中，杜绝反复踩坑。

项目设计系统文档：
`docs/design/UI_INTERACTION_SYSTEM.md`

---

## 🎯 何时使用

只要任务涉及或改变儿童可见 UI，即刻激活本 Skill：
- 田字格 / 米字格书写板、辅助线、笔顺动态回放；
- 拼音显示、声调对齐、朗读音标；
- 纸上伴读听写与屏幕双田字格自测听写；
- 生字选择器、单元课文抽屉、生字字典弹窗；
- 成就徽章墙、墨滴与星星动画、粒子礼花；
- 护眼关怀弹窗（`EyeCareModal`）；
- 任何“看不清 / 太小 / 点不到 / 容易误触 / 颜色太刺眼 / 拼音错位”等视觉与交互反馈。

## 👶 目标年龄与儿童认知画像

**核心用户群**：5–10 岁（学龄前大班至小学一至三年级儿童）。

### 儿童认知与生理特征：
1. **识字量处于爬坡期**：需要拼音、语音、图标、动效多通道辅助，避免大段纯文本说明。
2. **手部精细动作发育中**：握笔/手指点按抖动率高、触控精准度仅为成人的 40%~60%，边缘防误触需求极高。
3. **注意力跨度短**：单次有效专注 10~15 分钟，视觉焦点单一，容易被无关漂浮动画分心。
4. **挫败阈值极低**：对否定极为敏感，严禁刺目红叉与尖锐警报音。

## 📐 儿童人机工程硬性基线 (Hard Baselines)

### 1. 超大触控热区 (Touch Targets)
- **最小交互目标**：所有可点击元素尺寸 **$\ge 48\text{px}\times 48\text{px}$**。
- **主要操作按钮 (CTA)**：建议高度 **$52\text{px}\sim 64\text{px}$**（如“开始听写”、“写好啦”、“下一题”）。
- **按钮安全间距**：按键之间必须预留 **$\ge 12\text{px}\sim 16\text{px}$** 的安全间隙，严防邻近误触。
- **小图标防御**：若视觉图标较小（如 24px 图标），必须通过父级 Padding 扩展点击容器至 $\ge 48\text{px}$。

### 2. 护眼色彩与对比度 (Color & Contrast)
- **护眼纸张底色**：使用宣纸/书香柔和底色（`#FBF9F5`、`amber-50`、`stone-50`），杜绝全屏高光冷白（`#FFFFFF`）反光。
- **对比度标准**：
  - 核心生字与正文文本 $\ge 4.5:1$；
  - 大号标题与关键按钮非文本元素 $\ge 3:1$；
  - 严禁“浅黄底白字”或“深灰底暗黑字”。
- **警示色温和化**：纠偏使用柔和珊瑚橙（`amber-600`）或柔和粉（`rose-400`），**严禁使用高饱和度刺眼鲜红（`#FF0000`）**。

### 3. 字号与拼音排版标准
- 汉字主字号：手写田字格区域占据视觉主体（手机端 $\ge 280\text{px}$，平板端 $\ge 360\text{px}$）。
- 伴读/例句字号：正文 $\ge 18\text{px}$，辅助说明 $\ge 14\text{px}$，严禁用 $<12\text{px}$ 承载关键儿童指令。
- 拼音注音规范：采用 Unicode 标准带调字符（如 `ā, á, ǎ, à`），拼音字号约为生字的 1/3~1/2，水平严格居中对齐。

### 4. 非手势唯一入口 (No Gesture-Only Actions)
- 严禁将关键流程（如切换生字、清空笔迹、提交、退出）设计为**仅靠滑动/长按/双指缩放**触发。
- 手势可作为快捷辅助，但界面必须保留**清晰、直观、大尺寸的显式按钮**。

## 🔍 每次 UI 修改的“四步透视自查法”

每次修改儿童可见界面，必须进行四维审视：

### 1. 看 (Visual)
- 当前屏第一视觉焦点是否为核心教学任务（如田字格或听写词）？
- 主 CTA 按钮是否醒目？
- 对比度和字号在日光或低亮度下是否清晰？
- 有无元素截断、挤压、折行破裂？

### 2. 懂 (Cognitive)
- 5~8 岁低年级儿童能否不依赖成人看懂下一步？
- 文案是否具体友善（“我们再写一次吧！”）而非成人化（“输入校验失败”）？
- 界面是否保持“单屏单任务”，避免堆砌过多无关选择？

### 3. 操 (Operation)
- 点按热区是否确实 $\ge 48\text{px}$？
- 移动端虚拟键盘弹起或旋转屏幕时，操作按钮是否仍可见、不被遮挡？
- 破坏性操作（如清空错题）是否有二次防误触确认？

### 4. 扰 (Distraction)
- 练字与听写过程中，是否有无意义循环漂浮动效抢占孩子注意力？
- 提示音效是否柔和悦耳？
- 是否严格保证 20 分钟护眼机制不被篡改绕过？

## 🎬 动效与声音设计原则

每个动效与音效必须能够回答：
> **它在向儿童表达哪一个具体的教学或状态反馈？**

- **鼓励性动效**：
  - 单笔写对：水滴微动效或微光勾勒（0.3s~0.5s）；
  - 全字通关：彩带礼花（`canvas-confetti`）+ 星星点亮（1.0s~1.5s）；
  - 启动演示：慢速舒缓的笔锋流动（1.0s~2.0s）。
- **必须消除的动效**：
  - 无交互时的持续高频闪烁、晃动或未读红点抖动；
  - 容易引发焦虑的急促倒计时红闪。

## 🧪 UI 反馈蒸馏机制 (UI Feedback Distillation)

当用户或测试指出界面问题时（如“字太小”、“容易点错”、“背景太花”）：
1. **立即修复现场**：确保用户指出的问题立刻得到纠正；
2. **定性模式规律**：判定该问题属于哪一类儿童 UI 模式缺陷（热区、对比度、字号、层级、手势等）；
3. **全局检索同类**：在整个代码仓库中搜索存在类似隐患的其他组件，一并批量治理；
4. **固化蒸馏规则**：把修复总结提炼写入 `docs/design/UI_INTERACTION_SYSTEM.md` 和本 Skill，形成永久防御。
